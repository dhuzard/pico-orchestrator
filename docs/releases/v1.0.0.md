# PICO v1.0.0

First public release of PICO, the Pi Coding Orchestrator, under the MIT license.

## Highlights

**Routing and execution**

- Deterministic Claude/Codex routing across `CODEX`, `CLAUDE`,
  `CLAUDE_CODEX`, and `CODEX_CLAUDE_CODEX`.
- Fail-closed backend preflight with pinned Claude executable identity,
  authentication/version checks, and policy-valid availability rerouting.
- Post-route economy/standard/high capacity assignment with provenance-visible
  concrete model bindings.
- User-owned Claude/Codex model profiles via `pico models`, without allowing
  target repositories to weaken routing or capacity policy.
- Portable `pico` launcher for setup, update, doctor, sync, run, recovery,
  uninstall, and model configuration.
- Reproducible project pinning through `.pi/orchestrator.lock`.
- Mutable runtime provenance stored outside the cached Git checkout.
- Constrained, audited GitHub issue/PR lifecycle with professional templates,
  comments, title/body updates, dry-run plan hashes, and state-conflict checks.
- Unified parent/child orchestration provenance and trace rendering.
- Parent runs survive Pi turns, context compaction, reload and restart.
- Workers are bound to linked worktrees outside `.git`, and their scope is
  checked before every call.
- Headless runs (`pico exec start|status|cancel`) are idempotent and
  resumable. They restore the checkout after each child.
- Ubuntu and macOS CI coverage for the supported POSIX launcher contract.

**Multi-repository workspaces**

- A versioned workspace manifest and a read-only planner (`pico plan`)
  validate repository identities, pins and the task graph.
- `pico workspace schedule` runs tasks concurrently, bounded by
  `max_parallel` and by one child per repository. A failure blocks only its
  dependents, and a restart never relaunches a recorded task.
- Versioned contracts gate each step: `validate` runs checks on one commit,
  `publish` opens one draft PR per repository with links to its upstream
  PRs, and `promote` requires green CI. A merge is only ever observed.
- An optional token budget stops new launches once it is reached.

**Pico Garden**

- `pico watch` shows runs, workers, waves, the conversation and a timeline.
- `pico watch --workspace` shows every repository of a workspace.
- With `--controls`, actions run from the browser after a preview and a
  confirmation: validate, request a PR (with a one-time grant when the policy
  withholds it), check CI, promote, schedule, cancel, permission toggles and
  policy commits, and model changes. Requests are protected by a per-session
  token, Host and Origin checks, and an audit log.

## Installation

```sh
curl -fsSL https://raw.githubusercontent.com/dhuzard/pico-orchestrator/main/scripts/use-latest.sh | bash -s -- install
```

The GitHub CLI, authenticated, is needed for PICO's GitHub features: issues,
draft PRs and CI checks. The installed command is `pico`. While
`~/.local/bin` comes first on your `PATH`, it shadows the `pico` text editor,
which stays available as `/usr/bin/pico` or `nano`.

Then, from a target repository:

```sh
pico setup . --github-templates
pico doctor .
pico pin .
pico run .
```

Commit `.pi/orchestrator.lock` when the project needs a reviewed reproducible
orchestrator revision.

## Runtime storage

Default locations:

- cached code: `~/.cache/pi-coding-orchestrator/repo`
- runtime state/provenance: `~/.local/state/pi-coding-orchestrator`
- user model configuration: `~/.config/pi-coding-orchestrator/models.yaml`
- launcher: `~/.local/bin/pico`

Legacy untracked cached `provenance/runs/run-*.json` records are migrated into
the state directory on update.

## Recovery and uninstall

```sh
pico doctor . --json
pico reset-cache --force
pico uninstall
```

`reset-cache` discards/reclones cached code but preserves runtime state.
`uninstall` removes only the launcher unless explicit `--purge-cache`,
`--purge-state`, or `--purge-config` flags are supplied.

## Model configuration

Inspect effective bindings:

```sh
pico models show
```

Concrete models can be changed per capacity tier without editing routing
predicates. New Claude models require an explicit Claude Code backend model ID
and can raise, but never lower, built-in minimum backend-version constraints.

## Security and dependency refresh

v1.0 upgrades `@earendil-works/pi-coding-agent` to `1.0.2` and TypeBox to
`1.3.27`. The release CI requires `npm audit --audit-level=high` to pass.

This removes the high-severity `undici` and `brace-expansion` findings
present in the previous Pi 0.85.1 development dependency graph.

## Supported launcher environments

CI-supported:

- Linux
- macOS

Windows:

- WSL2 is recommended.
- A compatible Git-Bash environment may work.
- Native PowerShell is not a supported launcher surface in v1.0.
